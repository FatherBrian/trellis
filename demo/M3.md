# M3 demo: The catalog says pii

A data steward tags a column in the catalog, and the agent's next query comes back masked.
Contracts say what a table is; catalogs can add tags but never take one away; and when the
two disagree, the stricter answer wins.

## Run it

```bash
python -m pip install -e .
trellisd demo catalog-says-pii
```

By default the demo starts a small Iceberg REST catalog in-process, so it needs no Docker.
It creates `finance.gl.journal_entries` there, governed by the contract
[`examples/lakehouse/contracts/finance.gl.yaml`](../examples/lakehouse/contracts/finance.gl.yaml),
and then:

1. **report-bot queries the journal.** Ana's grant covers `finance`. The contract lets
   finance analysts read it, keeps only Ana's region (`region = {person.region}`), and
   says nothing about pii. Two rows of four come back, nothing masked.
2. **The steward tags `approver_email` as pii in the catalog** (the column property
   `trellis.column.approver_email.tags`). The next query comes back with that column masked,
   and the reason names the catalog and the metadata version the tag came from.
3. **`trellisd trace` shows who masked it and why:** the grant, the three checks, the
   contract and its version, every tag with its source, and the obligations with the policy
   each came from.
4. **An engineer adds a column, `notes`, that the contract doesn't list.** Trellis masks it
   as drift until the contract's owner classifies it, and writes one `catalog.drift` event
   to the ledger for that owner.
5. **The catalog marks the table `restricted`.** The contract says `internal`; levels are
   ranked (public < internal < confidential < restricted) and the higher one wins, so
   report-bot's ceiling denies the call and names the catalog as the reason. When the steward
   takes it off, the next query is allowed again.
6. **The catalog goes down.** Ten minutes on, Trellis answers from its cached copy and marks
   the decision stale. Twenty minutes on, past the 15-minute bound, it denies
   (`pip_unavailable`): it never guesses at tags it can't read.

The ledger then verifies: 9 events. Every decision records the contract version and the
catalog answer it used, so `trellisd explain <event> --replay` reproduces it later, even after
the catalog has changed.

The rows are sample data the demo passes in. Trellis reads only catalog metadata; the masks
and row filter are obligations that whatever runs the query applies (`Decision.enforce(rows)`
shows how).

## Against a real catalog

The demo takes any Iceberg REST catalog. It creates and changes
`finance.gl.journal_entries` there, so point it at a scratch one.

```bash
# The Iceberg reference server
docker run -d -p 8181:8181 apache/iceberg-rest-fixture:1.9.1
trellisd demo catalog-says-pii --catalog http://localhost:8181

# Apache Polaris (in-memory), with a catalog named lakehouse
trellisd demo catalog-says-pii --catalog http://localhost:8182/api/catalog \
    --warehouse lakehouse --token-env POLARIS_TOKEN
```

Both were run for this milestone, against local containers. Against a catalog it doesn't run,
the demo cuts its own connection in step 6 rather than stopping your catalog. Recorded
responses from both live under `tests/fixtures/iceberg/`, so the tests check the real shapes
without Docker; `TRELLISD_TEST_ICEBERG=http://localhost:8181` adds a live round trip.

## Step by step

```bash
export TRELLISD_CONFIG=examples/lakehouse
trellisd contracts list                         # every contract, its version and bindings
trellisd contracts import-odcs tests/fixtures/odcs/journal.odcs.yaml
trellisd catalog tags finance.gl.journal_entries   # merged tags, each with its source
trellisd schema --contract                      # JSON Schema for the contract format
```

## How tags merge

- **Contracts are the source of truth** for what a table is, who owns it, and who may use it.
  A contract can be written in Trellis's own format or read from an ODCS v3 file; the ODCS
  adapter refuses anything it can't map fully rather than guessing (see
  `examples/lakehouse/contracts/cash_positions.odcs.yaml`).
- **Tags are a union across sources.** A catalog can add `pii`; it can't remove a tag a
  contract gives. For ranked levels only the highest is kept.
- **Limits read every tag; selectors read only the contract's.** Ceilings, never-lists and
  masks look at the union, so a catalog tag can only take access away. Access rules,
  purposes and grant scopes match the contract's own tags, so a catalog tag can never make a
  grant or a rule match a table it otherwise wouldn't. A property test checks that adding a
  tag source never widens access. (The plan said each tag only narrows; that holds only if
  selectors ignore catalog tags, so this is how it's enforced.)
- **Levels expand in the safe direction.** A ceiling that lists `confidential` reaches
  `internal` and `public` too; a never-list or mask on `internal` covers everything above it.
- **Owner comes from the contract**, never from a catalog.
- **Fail closed.** Catalog answers are cached for five minutes (a missing table for 30
  seconds); change hooks can evict at once. Past the 15-minute staleness bound Trellis denies.
