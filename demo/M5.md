# M5 demo: The door

Two agents connect to one Reef in front of two MCP servers and see different tools. One
calls a tool outside its grant and is denied at the door: the ledger entry is already
there and the server's log is empty. Then the ledger's database goes away, and every call
is denied.

## Run it

```bash
uv sync --extra dev --all-packages     # or: pip install -e . -e reef
reef demo the-door
reef demo the-door --postgres postgresql://trellis:trellis@localhost:5432/trellis
```

Everything runs on this machine: a local OIDC IdP, Trellis, Reef, and two sample MCP
servers over streamable HTTP. `ledger` takes the person's own token (`obo` mode, exchanged
at the IdP for audience `ledger-mcp`); `hr` takes a service credential only Reef holds
(`brokered`). The config is in [reef/examples/the-door](../reef/examples/the-door).

1. **Two grants from sign-in.** report-bot for Ana, task "Q3 close", scope finance;
   people-bot for Ben, task "Headcount review", scope hr.
2. **Two tool lists from one Reef.** report-bot sees `ledger_journal_entries`; people-bot
   sees `hr_headcount` and `hr_payroll`. `ledger_post_adjustment` is a write, which no
   role of theirs allows, so neither sees it. Nobody wrote a persona: the lists come from
   the grants, and report-bot's description says its rows are limited to Ana's region and
   `approver_email` comes back masked.
3. **A read through the door.** The ledger server sees one call, as Ana, with her own
   token. Reef keeps 2 of 4 rows and masks `approver_email`.
4. **A call outside the grant.** report-bot calls `hr_payroll`. Ana may read payroll and
   report-bot's ceiling covers hr, but the grant is for the Q3 close, so the task check
   says no. The answer names the check and who could change it (Ana, for a grant whose
   task covers hr). The ledger already holds the decision and Reef's record that it
   blocked the call; the hr server's log is empty.
5. **The same tool for Ben.** people-bot calls `hr_payroll` through the same door; the hr
   server sees Reef's service account, never the agent's token.
6. **`trellisd trace`** shows who allowed the journal read, the three checks, where the
   tags came from, the obligations, and a new section, *At the door*: what Reef forwarded,
   with which credential, and how many rows it kept.
7. **The ledger goes away.** Both agents get no tools and every call is denied, because
   Trellis won't act unrecorded and Reef won't forward an unrecorded call. No call
   reaches a server. With `--postgres`, the demo cuts Postgres off behind a relay, then
   (step 8) brings it back, and the next call goes through without a restart.

## What's in the ledger

For each allowed call, in order: the `decision`, `credential.exchanged` (obo or agent
mode, never the token), an `enforcement` event with stage `forward` written before Reef
forwards, and one with stage `result` written before the agent sees the result. A deny is
the `decision` and an `enforcement` event with stage `blocked`. Each tool list is one
`tools.listed` event naming what was shown and what was hidden, and by which check.

`trellisd trace` lists every recent event, with `DOOR` and `LIST` lines for Reef's.

## Run Reef yourself

```bash
export TRELLIS_IDP_SECRET=... REEF_HR_TOKEN=...
reef serve --config reef/examples/the-door/reef.yaml \
    --trellis reef/examples/the-door/trellis --db postgresql://... --port 8190
```

An agent gets its grant token from `trellisd serve`'s `/token` endpoint (see
[M4](M4.md)) and connects to `http://localhost:8190/mcp` with
`Authorization: Bearer <grant token>`.

## What the tests check

`reef/tests/test_reef.py`: two grants see different tool lists from the same servers; a
denied call reaches nothing downstream; a stopped ledger denies every call (and, against
Postgres, recovers when it's back); each credential mode sends the right token (the
person's for obo, the agent's own for agent, Reef's for brokered); a tool dropped from its
contract leaves the next list; a lowered ceiling closes the door at once; no forward
without the enforcement event; a result that can't be recorded, or can't have its
obligations applied, is held back.
